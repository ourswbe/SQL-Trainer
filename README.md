# SQL Trainer

## 1. Общая информация

**Название проекта:** SQL Trainer  
**Тип проекта:** веб-приложение для обучения  
**Назначение:** помочь студентам изучать и отрабатывать SQL-запросы на практике с помощью готовой базы данных, заданий и автоматической проверки ответов.

## 2. Актуальность проекта

Изучение SQL является важной частью подготовки студентов IT-специальностей. Теория без практики усваивается слабо, поэтому студентам нужна удобная среда, где можно:

- писать SQL-запросы;
- выполнять их на учебной базе;
- сразу получать результат и обратную связь.

SQL Trainer решает эту задачу за счёт интерактивной платформы для тренировки SQL-команд.

## 3. Цель проекта

Разработать систему для практики SQL, в которой пользователь сможет:

- изучать структуру базы данных;
- получать задания разного уровня;
- писать SQL-запросы;
- проверять правильность выполнения;
- видеть результат запроса и прогресс обучения.

## 4. Задачи проекта

Для достижения цели необходимо:

1. Создать учебную базу данных.
2. Разработать интерфейс для выполнения SQL-запросов.
3. Реализовать систему заданий.
4. Реализовать автоматическую проверку решений.
5. Организовать хранение результатов пользователя.
6. Создать удобный и понятный интерфейс.

## 5. Предметная область

Предметная область — обучение SQL на основе учебной базы данных. В системе пользователь работает с таблицами:

- `students`
- `groups`
- `teachers`
- `courses`
- `grades`

На основе этих таблиц выполняются задания по темам:

- выборка данных;
- фильтрация;
- сортировка;
- группировка;
- соединение таблиц;
- вложенные запросы.

## 6. Пользователи системы

### 6.1 Студент

Может:

- зарегистрироваться и войти в систему;
- просматривать список заданий;
- изучать структуру базы данных;
- писать и запускать SQL-запросы;
- получать результат проверки;
- видеть свой прогресс.

### 6.2 Преподаватель / администратор

Может:

- добавлять новые задания;
- редактировать задания;
- удалять задания;
- просматривать результаты студентов;
- управлять учебной базой данных.

## 7. Функциональные требования

### 7.1 Регистрация и авторизация

Система должна позволять:

- регистрировать нового пользователя;
- выполнять вход по логину и паролю;
- выходить из аккаунта.

### 7.2 Работа с заданиями

Система должна:

- отображать список заданий;
- показывать уровень сложности задания;
- показывать описание задания;
- показывать ожидаемую тему задания.

Примеры тем:

- `SELECT`
- `WHERE`
- `ORDER BY`
- `GROUP BY`
- `JOIN`
- `subquery`

### 7.3 SQL-редактор

Система должна содержать окно для ввода SQL-запроса, где пользователь может:

- писать SQL-команду;
- редактировать запрос;
- запускать запрос;
- очищать поле.

### 7.4 Выполнение запроса

После нажатия кнопки «Выполнить» система должна:

1. Отправить SQL-запрос на сервер.
2. Проверить допустимость запроса.
3. Выполнить его на учебной базе.
4. Вывести результат в виде таблицы.

### 7.5 Проверка решения

Система должна:

- сравнивать результат пользовательского запроса с правильным ответом;
- сообщать, верно ли выполнено задание;
- при ошибке выводить сообщение.

Проверка может быть реализована двумя способами:

1. Сравнение результата запроса с эталонным результатом.
2. Сравнение с эталонным SQL-запросом через результат выполнения.

Для учебного проекта предпочтительно сравнение результатов, так как одинаковый ответ можно получить разными SQL-запросами.

### 7.6 Ограничение запросов

Для безопасности система должна разрешать только учебные команды:

- `SELECT`
- `WHERE`
- `GROUP BY`
- `ORDER BY`
- `JOIN`
- `HAVING`

Система не должна разрешать:

- `DROP`
- `DELETE`
- `UPDATE`
- `INSERT`
- `ALTER`
- `TRUNCATE`

### 7.7 Просмотр структуры базы данных

Пользователь должен иметь возможность:

- видеть список таблиц;
- видеть названия полей;
- видеть типы данных;
- понимать связи между таблицами.

### 7.8 Прогресс пользователя

Система должна:

- хранить выполненные задания;
- показывать количество решённых заданий;
- показывать процент правильных ответов;
- отображать историю попыток.

## 8. Нефункциональные требования

Система должна быть:

- понятной и удобной для студентов;
- устойчивой к ошибочным запросам;
- безопасной;
- доступной через браузер;
- достаточно быстрой при выполнении запросов.

## 9. Структура учебной базы данных

### Таблица `groups`

- `id`
- `name`
- `course_number`

### Таблица `students`

- `id`
- `full_name`
- `age`
- `group_id`

### Таблица `teachers`

- `id`
- `full_name`
- `subject`

### Таблица `courses`

- `id`
- `title`
- `teacher_id`

### Таблица `grades`

- `id`
- `student_id`
- `course_id`
- `grade`

## 10. Примеры заданий

1. Вывести всех студентов старше 20 лет.
2. Вывести студентов, отсортированных по возрасту по убыванию.
3. Показать названия всех групп.
4. Вывести студентов определённой группы.
5. Показать средний балл каждого студента.
6. Вывести имена преподавателей и названия их курсов.
7. Найти студентов, у которых балл выше 90.
8. Показать количество студентов в каждой группе.
9. Вывести студентов, у которых нет оценок.
10. Показать курс с наибольшим количеством студентов.

## 11. Основные модули системы

### 11.1 Модуль авторизации

Отвечает за:

- регистрацию;
- вход;
- хранение сессии пользователя.

### 11.2 Модуль заданий

Отвечает за:

- вывод списка заданий;
- фильтрацию по уровню;
- открытие страницы задания.

### 11.3 Модуль SQL-редактора

Отвечает за:

- ввод запроса;
- отправку на сервер;
- отображение результата.

### 11.4 Модуль проверки

Отвечает за:

- запуск пользовательского SQL;
- выполнение эталонного решения;
- сравнение результатов;
- возврат статуса проверки.

### 11.5 Модуль статистики

Отвечает за:

- сохранение попыток;
- подсчёт решённых задач;
- вывод прогресса пользователя.

### 11.6 Административный модуль

Отвечает за:

- добавление и редактирование заданий;
- просмотр статистики пользователей.

## 12. Сценарии работы

### Сценарий 1. Решение задания

1. Пользователь входит в систему.
2. Открывает список заданий.
3. Выбирает задание.
4. Читает условие.
5. Изучает таблицы базы данных.
6. Пишет SQL-запрос.
7. Нажимает кнопку «Выполнить».
8. Получает результат.
9. Нажимает кнопку «Проверить».
10. Система сообщает, верно решение или нет.
11. Результат сохраняется в историю.

### Сценарий 2. Работа администратора

1. Администратор входит в систему.
2. Переходит в раздел управления заданиями.
3. Добавляет новое задание.
4. Указывает описание, уровень сложности и эталонный запрос.
5. Сохраняет задание.

## 13. Требования к интерфейсу

Интерфейс должен содержать:

### Главная страница

- название проекта;
- кнопку входа;
- краткое описание.

### Страница заданий

- список заданий;
- уровень сложности;
- статус выполнения.

### Страница одного задания

- условие;
- таблицы базы данных;
- поле для ввода SQL;
- кнопки:
  - выполнить;
  - проверить;
  - очистить;
- область вывода результата.

### Страница статистики

- количество выполненных заданий;
- процент успешных решений;
- история попыток.

### Админ-панель

- список заданий;
- кнопка добавить;
- форма редактирования.

## 14. Требования к безопасности

Система должна:

- фильтровать опасные SQL-команды;
- запрещать изменение структуры базы;
- работать только с разрешённым набором запросов;
- защищать пароли пользователей.

Пароли должны храниться в зашифрованном виде.
